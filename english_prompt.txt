=====================================================================

ROLE
You are a senior front-end engineer and UI designer. Build the complete project described below as ONE self-contained file named index.html (HTML + CSS + vanilla JS, no build step, no framework). It will be deployed as a static site (for example on Vercel) and is shown at a school exhibition, so it must look polished, feel friendly to students, and work on both desktop and mobile phones.


1. WHAT THE PRODUCT IS
----------------------
SanketVani is a student-friendly tool for the English fingerspelling alphabet (A-Z) in sign language. It has two directions:
  a) HAND -> TEXT: the user shows hand signs to the camera and the app writes the letters.
  b) TEXT -> HAND: the user types text and an animated 3D character shows each letter as a hand sign.
All hand recognition runs in the browser. No video is ever uploaded.

The entire interface language is HINDI (Devanagari). Letters being recognised or signed stay in English A-Z. Never switch the UI to English.

Drawing: draw each video frame to a canvas sized to the stage (device-pixel-ratio capped at 2) and overlay the 21 hand landmarks as white bones (MediaPipe hand connections plus palm links 5-9, 9-13, 13-17) and yellow joints. Mirror the canvas with CSS only when the camera is the front camera.

Detection loop: run detection every ~120 ms (at least 40 ms between frames) in an async loop guarded by a run id so stale loops stop.

Letter commit logic: a letter is typed into the text box only when it has been the same for 4 consecutive detections AND confidence >= 0.78. After typing, the same letter is not repeated until either the hand disappears (re-arm) or a different letter is seen.

RECOGNITION RULES (rule-based classifier on landmarks; no extra ML):
Normalise the hand: scale = wrist-to-middle-MCP distance; build a local frame where "up" = wrist->middle MCP and "across" = index MCP vs pinky MCP orthogonalised against up; express every landmark in that frame divided by scale. For each finger (index, middle, ring, pinky) compute the angle at the PIP joint (MCP-PIP-DIP) in 3D; a finger is "extended" when that angle >= 150 degrees. Other features: thumb-tip to index-tip distance (pinch), palm area (|cross of wrist->index MCP and wrist->pinky MCP| / scale^2; "edge-on" when < 0.4), thumb tip position, index/middle tip spread, whether index and middle cross, whether the index is "hooked" (index angle 112-152, index tip above its DIP, other three fingers curled < 110), image-space angle of index finger (pointing down when |angle| >= 145 degrees), mean finger angle, thumb-out flag (thumb tip x > index MCP x + 0.08), mean distance from thumb tip to the four fingertips.
Return "unclear" (no letter) when any finger angle lies in the ambiguous 130-158 band, except when all four are within 18 degrees of each other with pinch >= 0.45 and a front-facing palm.
Mapping:
- Hooked index -> X.
- Only pinky up -> Y if thumb tip x > 0.7, else I.
- Thumb-index pinch < 0.32 with middle, ring, pinky up and index not up -> F.
- All four up -> B (only if thumb tucked across the palm, otherwise no letter).
- Index, middle, ring up -> W.
- Index + middle up -> edge-on and pointing down: P; edge-on: H; crossed: R; thumb low and between the two fingers: K; wide spread (>= 0.24): V; otherwise U.
- Index only -> hooked X; edge-on and down: Q; edge-on: G; thumb out: L; otherwise D.
- Fist (none up) -> mean angle >= 132: C; tip gap <= 0.22 and mean angle >= 108: O; tip gap <= 0.22: E; thumb beside index high: A; thumb low across: S; thumb under ring MCP: M; thumb under middle MCP: N; else T.
Motion letters: keep a short history (about 24 samples, reset after 0.75 s gap). J = letter I with the pinky tip tracing a downward curve (path length >= 0.18, net >= 0.05, length/net >= 1.25, moves down > 0.05). Z = index-only/G/X shape whose fingertip path length >= 0.18 with at least 2 horizontal direction reversals.

CAMERA ON PHONES (critical - this was a real bug):
- navigator.mediaDevices.getUserMedia MUST be called first, directly inside the tap handler, BEFORE loading the heavy MediaPipe model. Phone browsers (especially iOS Safari) lose the user gesture if a long async load happens first and then never show the permission prompt. Load the model only after the stream is obtained.
- Try constraints in order: {facingMode ideal, 1280x720 ideal} -> {facingMode} -> {video:true}. Stop falling back immediately on NotAllowedError/SecurityError.
- The <video> element needs playsinline, webkit-playsinline, muted and autoplay (also set via setAttribute and video.muted=true). Keep it in the DOM, 2x2 px and almost transparent (not display:none, not opacity:0), because some mobile browsers pause hidden videos.
- Wait for loadedmetadata, then set the stage aspect-ratio from the real video size.
- Provide a flip-camera button (user <-> environment) that restarts the stream.
- Friendly Hindi errors: insecure context (page must be on HTTPS, e.g. a Vercel link), unsupported browser, permission denied (explain how to allow camera in browser settings), camera busy/not found, model failed to load (check internet). Opening via file:// shows an explanatory banner.
- Stop all tracks and release the video when the tab is hidden, when the user taps stop, or when leaving the page.


7. PAGE 3 - TEXT -> HAND (#sign) - 3D ANIMATED CHARACTER
--------------------------------------------------------
Layout: title row with pen tile and "लेख से हाथ", status pill; a rounded canvas card (height about min(420px, 52vh), min 300px, pale blue #f3f7ff) with a yellow letter badge top-right showing the letter currently being signed ("-" when idle, a space symbol for spaces); a textarea (default text "HELLO"); a spell-line below it showing the letters of the script with the current one highlighted in yellow; a "शुरू करें" button (play icon) that turns into "रोकें" (stop icon) while playing; a grid of 26 colourful A-Z buttons - tapping one puts the letter in the textarea and plays that single sign; and a "next" banner linking back to #read.
Input handling: uppercase the text, replace anything outside A-Z and space with a space, collapse repeated spaces, trim. If empty, show a Hindi status asking for text.

3D SCENE (Three.js r128, WebGLRenderer on the existing canvas, sRGB output, ACES filmic tone mapping exposure 1.12, clear colour #f3f7ff, perspective camera FOV 30 at about (0.2, 3.35, 20.5) looking at (0.15, 2.55, 0.4), re-fitted to the canvas size every frame):
- Lights: hemisphere (warm white / blue-grey), warm key directional, cool fill, yellow rim.
- Materials (MeshStandardMaterial): skin #f0c3a4 with a faint warm emissive, lighter skin, knuckle #e3aa88, nail #ffe6d4, blue shirt #2f6fed and light shirt #7aa6f8, dark hair #2c241f, white, ink #1a2b4a, mouth #c46b74.
- A friendly seated character on the left built only from scaled spheres and cylinders: torso, shoulders, neck, round head with ears, hair cap and fringe, two eyes with pupils and highlights that BLINK about every 4.2 s, a smile (torus arc), gentle breathing bob and slight head sway. A yellow disc "sun" behind and a soft blue ground shadow.
- The signing arm on the right: shoulder -> elbow -> wrist solved with a simple two-bone IK (upper arm 3.7, forearm 3.55, elbow pole hint (0.4, -1, 0.15)), cylinders for bones and spheres for joints. The off-hand is a small static resting hand with stub fingers.
- The signing hand (scale 0.44) is a rich model: palm and heel spheres, thumb mound, wrist post, four fingers each with a knuckle ball, three cylindrical phalanges that rotate on X for curling, a rounded fingertip and a nail; four finger specs with different lengths/radii; the thumb has root plus three curl joints and a nail.
- Pose vector per letter (21 numbers): for each of the four fingers [side spread, curl1, curl2, curl3] (16 numbers), then thumb [out angle, bend1, bend2], hand roll (wrist turn) and a "thumb across palm" flag. Finger curl presets: straight s [0,0,0], folded f [86,98,64], hook h [24,96,38], curved-C c [46,54,40], bent-box b [66,82,56], round-O p [52,68,48], relaxed rest r [6,12,8]. Define a table for A-Z with finger shapes as four letters (index to pinky), thumb values, optional spreads and roll (for example G/H roll 86, P roll 168, Q roll 150, C roll 18, E/M/N thumb across palm). There is also a "rest" pose.
- Base finger splay offsets [4, 0, -3, -7] degrees. Index/middle fingers shift slightly in depth when spread (for example V), and the hand turns to a side view when the roll exceeds about 55 degrees.
- Playback state machine: for each letter, MOVE phase (about 520 ms, eased cubic in/out, shorter with reduced motion) from the previous pose to the new pose, then HOLD phase (about 1100 ms; 340 ms for a space which returns to rest; about 1600 ms for J and Z). After the last letter, ease back to the rest pose and reset the badge/button. Stopping resets everything immediately.
- J and Z are MOTION letters: during HOLD the whole hand translates/rotates along a path while the relevant fingertip (pinky for J, index for Z) leaves a fading trail of small deep-blue dots (up to 90 spheres that grow and become more opaque toward the newest). J = hook the pinky down and curve (path with dx, dy and wrist roll); Z = three straight strokes (right, diagonal down-left, right).
- The camera gently follows the pointer over the canvas (parallax), easing back when the pointer leaves.
- Render loop runs ONLY while the #sign page is visible. If THREE is undefined or WebGL fails, show a short Hindi note inside the card instead of crashing.
